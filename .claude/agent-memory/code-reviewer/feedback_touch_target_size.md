name: 모바일 아이콘 버튼 터치 타겟 크기 체크
description: p-2 등 패딩만으로 아이콘 버튼을 만들면 44px 미만이 되기 쉬움 — 리뷰 시 계산해서 지적할 것
type: feedback
---

이 프로젝트(375px 기준 모바일 전용 PWA)의 아이콘 버튼들은 `p-2 rounded-full` + heroicons(width/height 22~26)로 구성되는 경우가 많다.

예: `components/PhotoCarousel.tsx`의 확대 모달 좌/우 이동 버튼 — 2026-07-29 리뷰에서 지적 후 `w-11 h-11`(44px)로 수정 완료. 같은 파일의 닫기 버튼은 여전히 icon 22px + p-2*2 = 38x38px(미수정, 우선순위 낮음). 같은 파일의 **메인 컨트롤 바** 이전/다음 버튼(확대 모달과는 다른 위치)은 아예 고정 크기/패딩이 없어 icon 26px 그대로 26x26px — 2026-07-29 재리뷰에서 신규 발견.

`components/MusicPlayer.tsx`(전역 하단 고정 뮤직 플레이어)도 동일 패턴: 재생/일시정지 버튼만 `w-11 h-11`(44px)이고, shuffle/backward/forward/재생목록(Bars3Icon) 4개 버튼은 고정 크기 없이 아이콘(20~24px) 그대로가 클릭 영역. 5개 버튼 전부 `aria-label` 없음(2026-07-29 리뷰에서 발견, 🟡, 최초 커밋부터 존재하던 기존 이슈이며 아직 미수정).

iOS HIG 권장 최소 터치 타겟은 44x44pt, Android는 48x48dp다. `p-2`(8px) 패딩만으로는 icon이 26px 이상이어도 44px에 못 미치는 경우가 흔하다.

**Why:** 실제 터치 오조작(다른 버튼 오터치, 터치 반응 안 됨)으로 이어질 수 있는 모바일 UX 이슈이며, 코드만 봐서는 놓치기 쉬운 수치 계산이 필요하다.

**How to apply:** 아이콘 버튼을 리뷰할 때 `icon size + padding*2`를 직접 계산해서 44px 미만이면 🟡로 지적하고, `w-11 h-11`(44px) 같은 고정 크기 flex 중앙정렬 또는 padding 증가(`p-2.5`~`p-3`)를 제안한다. 단, 기존에 이미 존재하던 버튼(예: 닫기 버튼)까지 매번 전면 지적하기보다는, 리뷰 대상 diff에서 새로 추가된 버튼 위주로 우선 지적하고 기존 버튼은 참고로 언급.
